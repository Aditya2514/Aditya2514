# Atlas profile README

The profile is a set of animated SVGs generated by Python (standard library only) and
shown through plain `<img>` tags, so nothing in it needs scripts, web fonts or external files.

## Rebuild

```sh
python3 scripts/build_atlas.py             # offline, from cached data; same input gives the same files
python3 scripts/build_atlas.py --refresh   # ask GitHub first (needs GH_TOKEN)
python3 -m unittest discover -s tests -v
```

The `Live signal` workflow runs the `--refresh` build every six hours and commits only when
something changed. A failed or rate-limited request keeps the last good data and its date.

## Where things live

| To change | Edit |
| :-- | :-- |
| Colours, fonts, shared shapes, the contour-map generator | `scripts/atlas_kit.py` |
| Hero: name, thesis lines, credentials, map markers | `scripts/atlas_hero.py` |
| The three project cards and their diagrams | `scripts/atlas_featured.py` |
| Repository cards, build kit, signal, route, contact, buttons | `scripts/atlas_scenes.py` |
| What GitHub data is fetched and cached | `scripts/atlas_data.py` → `data/atlas.json` |
| Repository titles, descriptions, order, tools | `profile.json` |
| Page text and links | `README.md` |

Generated output goes to `assets/atlas/`. Do not edit those files by hand; the next build overwrites them.

`README.md` keeps two generated blocks. Leave both marker pairs in place:
`PROJECT-LOBBY` (the repository grid) and `MISSION-FEED` (latest commits).

## How it adapts

- **Phones.** Each scene has a `-mobile` twin built from the same 432-wide tiles, stacked instead of
  side by side. `<picture>` switches at 600px. Repository cards switch to a compact card.
- **Reduced motion.** Every SVG turns its animation off under `prefers-reduced-motion` and shows the
  finished state of each diagram.
- **New repositories.** Any public, non-fork, non-archived repository gets a card automatically, with
  a contour patch generated from its name. Add an entry under `overrides` in `profile.json` for a
  better title, description or stack.

## Honesty rules

The numbers in the Signal scene come from GitHub's contribution calendar and commit history.
The project diagrams are illustrations of each mechanism and are labelled as such.
Text that comes from GitHub (repository names, descriptions, commit titles) is escaped before use.

## Older generations

`assets/mission`, `assets/arena`, `assets/catalog`, `assets/cinema`, `CINEMA.html` and their
`build_*.py` scripts belong to earlier designs. The README no longer shows them and the workflow no
longer rebuilds them. `build_atlas.py` still reuses `build_catalog.py`, `build_signal.py`,
`build_rhythm.py` and `github_activity.py` for fetching and summarising data.
